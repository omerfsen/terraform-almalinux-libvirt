# terraform-almalinux-libvirt

Build AlmaLinux 9 VMs on KVM/libvirt with Terraform. One base image is fetched
once and shared; every VM is a copy-on-write overlay on it, configured through
cloud-init.

```hcl
vms = {
  "alma9-01" = { ip = "192.168.122.240/24" }
  "alma9-02" = { memory = 8192, vcpu = 4, disk_size = 60, extra_disks = [100] }
  "alma9-03" = {}   # no ip = DHCP
}
```

```
terraform init && terraform apply
```

## Layout

| Path | What |
|---|---|
| `provider.tf` | provider and version constraints |
| `variables.tf` | every input, typed and described, no defaults |
| `terraform.tfvars` | every value — the only file you normally edit |
| `main.tf` | the shared base image, then one `module.vm` per entry in `vms` |
| `outputs.tf` | names, UUIDs, MACs, addresses, ready-made ssh and console commands |
| `modules/vm/` | one VM: disks, cloud-init, the domain |
| `modules/vm/templates/` | cloud-init user-data and network-config |

Variables carry no defaults on purpose: a value you forgot fails at plan time
instead of quietly taking one that was buried in the code.

## What you get

- **Any number of VMs** from one map, each able to override memory, CPUs, disk
  size, address, network, extra disks and autostart.
- **Static addressing or DHCP** per VM, through cloud-init network-config v2
  rather than hand-written `ifcfg` files, and converted to NetworkManager
  keyfiles on first boot.
- **Copy-on-write disks.** The base image is stored once. A 30 GiB VM disk
  occupies about 200 KiB until the guest writes to it.
- **The image is fetched for you** from a URL — nothing has to be downloaded
  onto the hypervisor first.
- **SSH hardening** following the [ssh-audit RHEL8 hardening guide](https://www.ssh-audit.com/hardening_guides.html#rhel8):
  host keys regenerated (the image ships the same ones to everybody), weak
  moduli pruned, the ECDSA host key dropped, and ciphers, MACs, key exchange
  and signature algorithms restricted.
- **Serial console** wired up, so `virsh console <name>` shows the whole boot.
- **UEFI, Secure Boot, TPM 2.0, SPICE/VNC/headless, extra disks, CPU mode and
  machine type** are all switches.
- **Graceful shutdown on destroy** — an ACPI shutdown with a timeout, instead
  of pulling the plug.

## Supported releases

Tested end to end on this hypervisor, same configuration, only `image_url`,
`image_name` and `image_capacity` changed:

| Release | Result |
|---|---|
| 9.8 | static IP, NetworkManager keyfile after `nmcli connection migrate`, ECDSA host key removed, ipv6 off, SELinux enforcing |
| 10.2 | same, and cloud-init picks the `network-manager` renderer itself, so the keyfile is written directly |

`/etc/sysconfig/network-scripts` does not exist on 10.x, which is why the
configuration describes the network once in cloud-init network-config v2
rather than writing `ifcfg` files. 10.x also needs an x86-64-v3 host CPU:

```
/usr/lib64/ld-linux-x86-64.so.2 --help | grep x86-64-v3
```

## What you need

| | |
|---|---|
| Terraform | >= 1.16 (tested on 1.16.5) |
| Provider | `dmacvicar/libvirt` ~> 0.9.9 |
| Hypervisor | libvirt with a storage pool and a network; `swtpm` only if `tpm = true`, OVMF only if `firmware = "efi"` |

## Upgrading from the 0.8 provider

Version 0.9.0 of the libvirt provider is a redesign, not a new release: HCL now
maps almost one-to-one onto libvirt XML, and
[the author states](https://github.com/dmacvicar/terraform-provider-libvirt/releases/tag/v0.9.0)
there is no automated way to migrate the HCL. This repo was rewritten against
the new schema. If you are pinned to the old one, the legacy provider lives on
in the project's `v0.8` branch.

State does not carry over. Destroy with the old code, then apply with this.

## Notes

- `image_capacity` has to be set because the image URL redirects to mirrors
  that do not always send `Content-Length`, and the upload then fails. Read it
  with `qemu-img info <file> | grep 'virtual size'`.
- `image_url` takes a local path or a `file://` URL as happily as `https://`.
  Worth doing if your nearest mirror is slow: measured from one host, the
  AlmaLinux image pulled at ~14 MB/s and the Rocky one at ~2-3 MB/s. The image
  is fetched once and shared, so this is a per-image cost, not per VM.
- `selinux_mode = "disabled"` and any `grub_*` option need one reboot to take
  effect; `reboot_after_first_boot` does that at the end of first boot.
- `crashkernel=auto`, which earlier versions of this repo set, is not carried
  over: EL9 ignores it.
- Changing cloud-init settings does not reconfigure a running VM. cloud-init
  runs once per instance id, so the VM has to be rebuilt.
